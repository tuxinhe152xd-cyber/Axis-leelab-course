# 判斷與拆解

## 判斷：要不要用 Agent
原則：從最簡單的開始，有需要才加複雜度。Agent 會增加延遲與成本，錯誤也會累積。

依序問使用者：
1. 輸入的說法是不是每次都不一樣、需要理解意思？（是 → 偏向 Agent）
2. 步驟是不是固定、輸入格式是不是固定？（是 → 固定流程就夠）
3. 需要查資料或改資料嗎？（需要 → 加工具）
4. 做錯的後果嚴重或不可還原嗎？（是 → 要人確認）
5. 需要的資料現在存在嗎？（不存在 → 先整理資料，再談 Agent）

| 情況 | 適合 | 例子 |
|---|---|---|
| 步驟固定、輸入格式固定 | 固定流程（程式或 n8n） | 每天固定抓一個報表 |
| 輸入說法不固定、要理解意思 | Agent | 「十盒餅乾」「老樣子再一份」 |
| 要判斷、又要查或改資料 | Agent + 工具 | 收訂單並扣庫存 |

給結論時要說：結論是什麼、依據是哪幾題的答案、哪裡仍不確定。

## 拆解：六個問題
1. **我現在是怎麼做的？** 請使用者把手動做的每一步寫出來，先不要想 AI。
2. **每一步的四件事：** 什麼觸發、用了什麼資料、做了什麼動作、結果給誰。
3. **每一步屬於哪一類？** 見下表。
4. **資料在哪裡？** 還在紙本或腦袋裡的，先整理成表。
5. **被動還是主動？** 有人傳訊息才動，還是到時間自己動（排程）。
6. **先做最小的一步，並寫一句驗收。**

### 三類分工
| 這一步需要… | 交給誰 | 例子 |
|---|---|---|
| 理解意思、說法不固定 | Agent（模型） | 看懂「十盒餅乾」 |
| 固定規則、算數字 | 工具（程式） | 扣庫存、判斷是否低於安全庫存 |
| 後果嚴重或不可逆 | 人確認 | 大額訂單、刪除資料 |

提醒：數字與規則一律交給工具算，不要讓模型「大概算」。

### 例外
每一步都問：失敗或被拒絕時，要怎麼回覆？（庫存不足、商品不存在、查不到資料、沒有權限）
