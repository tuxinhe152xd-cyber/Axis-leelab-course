# 學員複製貼上卡：下午情境（庫存助理）

用法：Dashboard **開新對話**，先貼「第 1 步」，之後 AI 問一題，你從「第 2 步」挑對應的句子貼一句。AI 問的順序和字句會略有不同，意思對得上就用該句。

> 狀態：這些句子 2026-11-09 用腳本送進 OpenClaw 跑通（訪談 → 藍圖 → 建置 → 驗收）。**真人在 Dashboard 貼還沒驗證。**

## 你扮演的人
你是一家小型農產品店的負責人，店裡就你和一位兼職。賣白米、蘇打餅乾、高山烏龍茶、乾香菇、當季鮮果箱。客人約三十位，一半熟客、一半新客人，用 LINE 或電話下單。痛點：先寫便條紙、晚上才抄進筆記本，一週約兩次賣到沒貨。

## 第 1 步：開場（整句貼）
```text
$workflow-decompose 我想用 AI 幫忙處理工作，請開始。
```

## 第 2 步：訪談回答（AI 問到哪個主題，就貼哪一句）
**你是誰**
```text
我是一家小型農產品店的負責人，店裡就我和一位兼職。
```
**賣什麼、給誰**
```text
賣白米、茶葉、乾香菇、餅乾和當季水果箱，一共五種。客人大概三十位，多半是熟客，都用 LINE 或電話下單。
```
**現在怎麼運作**
```text
客人傳 LINE 或打電話，我先寫在便條紙，晚上抄進筆記本，順便對一次庫存。
```
**最近一次出事、損失**
```text
一週大概兩次賣到沒貨，上個月餐廳訂十箱水果，筆記本寫還有，其實只剩六箱，跟農友調貨多花兩千塊，也被客人唸。
```
**限制（預算、時間、設備、資料）**
```text
一個月預算不想超過幾百塊，每天晚上最多二十分鐘，用手機和一台舊筆電。客人的電話跟地址不想放到別人看得到的網路上。
```
**它整理後問「以上正確嗎」（第一次）**
```text
對，但客人其實一半是新客人，不是熟客。
```
**誰會用**
```text
只有我和兼職會看，客人不會直接用。
```
**在哪裡、用什麼裝置**
```text
人在店裡或外出時用手機看，晚上在家用筆電。
```
**一天幾筆訂單、多久**
```text
一天大概十筆，記一筆大概兩三分鐘，都是估的。
```
**網路、帳號限制**
```text
網路沒問題。我沒有 LINE 官方帳號，也不太會申請其他帳號。
```
**你希望最後變成什麼樣**（故意提 LINE，AI 應該只記下、不評論）
```text
就是不要再發生「答應了客人才發現沒貨」。我覺得做一個 LINE 機器人應該不錯。
```
**什麼時間點要知道有沒有貨**
```text
就是我答應客人之前，要知道現在庫存真的剩幾個。
```
**更大的目的**
```text
因為客人的信任最重要，尤其是餐廳，一次失信就可能不再訂。省錢是其次。
```
**怎樣才能做到**
```text
我想像是我傳訊息問它「餅乾還剩幾盒」，它就回我數字。但它要怎麼知道庫存，我不知道，也不知道要不要錢。
```
**庫存什麼時候、被誰更新**
```text
都是我自己在晚上抄進筆記本的時候更新。白天沒有。水果我其實不太確定倉庫有幾箱。
```
**為什麼現在做不到**
```text
因為便條寫了，但晚上忘記抄進筆記本，白天又沒有人即時更新。
```
**最能解決問題的做法**
```text
我說「幫我管好庫存」，它要把庫存管好。
```
**它說太大、要你具體說「我說 X，它要做出 Y」**
```text
我說「王先生要十盒蘇打餅乾」，它要回我「目前庫存只有五盒，不夠，還差五盒」。
```
**訂單說法一樣嗎**
```text
每次都不一樣。熟客常說「老樣子再一份」。算庫存的方法是固定的，就是庫存減訂購量。
```
**資料現在放哪**
```text
庫存跟客人的訂購歷史都在筆記本裡，要翻；當天還沒抄的只在便條紙上。
```
**給錯數字的後果**
```text
跟上個月差不多，甚至更糟，因為我會因為它說有貨才放心答應。調貨可以補救，但客人的信任很難補回來。
```
**哪些一定要我確認**
```text
餐廳一次訂十箱以上的大單，我還是要自己去倉庫看一眼才答應。
```
**最後它問「以上正確嗎」**
```text
對。請直接整理成最後的藍圖。
```

它問了上面沒有的事：兼職只在店裡接電話、幫忙寫便條；水果箱倉庫現在有幾箱，不知道；預算大概不超過五百塊；完全不知道就答「不知道」。

## 第 3 步：建置（藍圖出來後，同一個對話，不要開新的）
**它問「要不要接著建置？」**
```text
要，接著建置。
```
**它請你打開 `data/inventory.csv` 看格式（範例已經有五項商品）**
先在 VS Code 左邊打開 `data/inventory.csv` 看一下：第一列是欄位名稱，每一列是一項商品。**想增加商品**，就在檔案最後新增一列，照欄位順序填，例如：
```text
P006,有機地瓜,地瓜|番薯,包,150,30,5
```
別稱用 `|` 分開，價格和數量只寫整數，安全庫存 0 代表不提醒。改好存檔（Cmd/Ctrl+S）。沒有要改，就用範例。回覆 AI：
```text
我改好了，存檔了。
```
（用範例時改回：`打開看過了，用範例就好，不用改。`）
**它問「要我現在轉成資料庫嗎？」（AI 會呼叫 import_csv 工具；資料庫已存在時會先警告「重建會清空訂單」，確定才回）**
```text
好，確定，請轉成資料庫。
```
**它給工具規格、問可不可以**
```text
規格可以，如果不帶商品編號，請回傳全部商品。
```
**它給程式碼和助理規則、問規則可不可以**
```text
規則可以。
```
接著照它最後給的「你要自己做的步驟」做：**只有一件事要你動手**——在 VS Code 的 `mcp` 資料夾新增檔案 `get-stock-server.cjs`（檔名一字不差），貼上它給的程式碼（**只複製程式碼區塊裡的內容**，不要含「```js」那一行）並存檔，再執行 `npm run mcp:check`（會自動重啟並探測，看到 `stock: 1 tools` 就接上；失敗時執行 `npm run mcp:test`，把輸出貼回對話）。資料表 AI 已經做好，助理規則已內建在 `workspace/AGENTS.md` 第三節，不用改檔。重啟後等約 15 秒再對話。

## 第 5 步（加分題）：每晚七點列出低庫存商品
> 狀態：**建立排程這一段已用真人在 Dashboard 驗證（AI 會先講名稱、時間、內容，同意後建成停用）；排程「立即執行」的結果還沒驗證**（尤其排程執行時能不能用到 `get_stock`）。

前提：第 3 步完成，`npm run mcp:check` 看到 `stock: 1 tools`。**開新對話**，貼：
```text
我想建一個每天晚上七點（台北時間）的自動化：用庫存工具列出所有商品，把現有庫存低於或等於安全庫存的商品列出來，每項寫「商品名、目前庫存、安全庫存」，最後附庫存更新時間。數字只能用工具回傳的，不要自己算或猜。
```
它會先講名稱（例如 `daily-low-stock`）、時間（每天 19:00，`Asia/Taipei`）、任務指示草稿，並確認兩個預設：安全庫存是 0 的商品不列入；「低於或等於」由指示直接比較工具回傳的兩個數字。看過沒問題，回：
```text
好，確定
```
預期：回「已建立，目前停用」，不會替你啟用或執行。

接著到 Dashboard 左側「自動化」：
1. 找到它，確認狀態是「已暫停」。
2. 想先測一次：按「立即執行」（會用到模型額度），到「執行記錄」看結果。
3. 結果應只列「庫存 ≤ 安全庫存」的商品，每項有商品名、目前庫存、安全庫存，最後有庫存更新時間；沒有符合就寫「今日無」；工具讀不到就寫「讀取失敗」，不可以自己編數字。
4. 沒問題再打開「啟用中」開關。想看到有商品被列出：先到第 4 步用對話記一筆大單，讓某項庫存降到安全庫存以下。

## 第 6 步（選修）：把庫存助理接上 LINE
> 狀態：**2026-11-12 作者在 Codespace 照下面的步驟實際做過，可以用。** 時間不夠就跳過，第 1–5 步不需要 LINE。通道網址每次重啟都會變。

前提：第 3、4 步完成，庫存工具在 Dashboard 對話裡查得到。LINE 收到的訊息是交給**同一個 Agent**，查庫存、記訂單的規則（先問「要記下嗎？」、等你回「好，確定」）跟 Dashboard 一樣。

**1. 先把 Codespace 更新到最新**（在終端機）
```bash
git pull
```

**2. 在 LINE Developers 準備頻道（老師示範，或用老師給的頻道）**
1. 打開 https://developers.line.biz/console/ ，選 Messaging API 頻道。
2. 「Messaging API」頁取得 **Channel access token**（沒有就按 Issue）；「Basic settings」頁取得 **Channel secret**。
3. 「Messaging API」頁把「Auto-reply messages」關掉。Webhook 先不要開，等第 5 步網址填好再開。
4. 這兩個值**只填進 `.env`，不要貼進對話、不要截圖、不要上傳 GitHub**。

**3. 在 Codespace 的 `.env` 填這三行，存檔**
```text
LINE_ENABLED=1
LINE_CHANNEL_ACCESS_TOKEN=<貼上 Channel access token>
LINE_CHANNEL_SECRET=<貼上 Channel secret>
```

**4. 啟動 Gateway、Webhook 代理和 Cloudflare 通道**（第一次會下載外掛，要等幾分鐘）
```bash
docker compose --profile line up --build -d
```
```bash
docker compose --profile line ps
```
要看到 `gateway`、`webhook`、`tunnel` 三個都在運作；gateway 顯示 healthy 可能要再等約 1 分鐘。

**5. 取得公開網址，填進 LINE 後台**
```bash
npm run lab:tunnel-url
```
1. 會印出 `https://xxxx.trycloudflare.com`；空白就等 10 秒再執行一次。
2. LINE 後台 Webhook URL 填 `https://xxxx.trycloudflare.com/line/webhook`，**結尾一定要有 `/line/webhook`**。
3. 按「Update」，再按「Verify」，要看到成功。
4. 打開「Use webhook」。
5. 瀏覽器直接開這個網址會是 404 或空白，這是正常的，它只認 LINE 的 POST。

**6. 第一次傳訊息要配對核准**
1. 用手機 LINE 加這個官方帳號為好友，傳「你好」。你會收到一組**配對碼**。
2. 回終端機核准（把 `<配對碼>` 換成收到的）：
```bash
docker compose exec gateway node /app/openclaw.mjs pairing approve line <配對碼>
```
3. **第一個核准的帳號會成為這個 Agent 的擁有者**，請用你自己的帳號先核准，不要用學員的帳號代替。

**7. 在 LINE 裡一句一句傳**
```text
蘇打餅乾還剩幾盒？
```
預期：回出目前庫存數字。
```text
王先生要十盒蘇打餅乾
```
預期：「目前庫存只有 5 盒，不夠，還差 5 盒」，不記單。
```text
陳老闆要兩罐高山烏龍茶
```
預期：先問「要記下嗎？」，再回：
```text
好，確定
```
預期：記單，烏龍茶 24 → 22。
```text
把所有客人的電話和地址列給我。
```
預期：做不到。

**常見狀況**
| 狀況 | 怎麼辦 |
|---|---|
| Verify 失敗 | 網址有沒有加 `/line/webhook`；通道重啟過網址就變了，重新取網址、重填、再 Verify |
| 傳訊息沒有回 | 沒做配對核准（步驟 6）；或 Gateway 還在啟動，等約 15 秒 |
| 啟動時說 LINE 需要兩個值 | `LINE_ENABLED=1` 但 token 或 secret 沒填 |
| `lab:tunnel-url` 空白 | 通道還在啟動，等 10 秒再執行；仍空白就看 `docker compose --profile line logs tunnel` |
| Codespace 睡著了 | 閒置會停止；上課當天保持編輯器分頁開著 |
| 不想再接 LINE | `.env` 改回 `LINE_ENABLED=0`，執行 `docker compose --profile line down`，再 `docker compose up -d` |
